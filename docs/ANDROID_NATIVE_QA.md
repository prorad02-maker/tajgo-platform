# Проверка TajGo в Android

Этот сценарий запускает настоящие Android-плагины Firebase Auth, геолокации,
настроек и карты. Профили, заказы и остальные репозитории заменены изолированными
адаптерами из `test/support/`. Рабочий Firebase не используется для тестового входа
или записи заказов. Отправки настоящих SMS нет.

## Запуск

Нужен отдельный Android-эмулятор с Google APIs, Android SDK platform-tools,
Flutter из `pubspec.yaml`, Firebase CLI и свободный порт 9099.

Из корня проекта запустить локальный Auth:

```powershell
firebase emulators:start --only auth --project demo-tajgo-android --config scripts/firebase.android-smoke.json
```

В другом терминале:

```powershell
flutter pub get
.\scripts\run_android_smoke.ps1 -Device emulator-5554
```

Если Flutter отсутствует в PATH, передать `-Flutter C:\flutter\bin\flutter.bat`.
Журнал сохраняется в `build/android-smoke/android-native-test.log`; каталог можно
поменять через `-OutputDirectory`.

Сценарий специально отказывается работать с физическим телефоном. Он меняет
разрешения **тестовой установки** `tj.tajgo.app`, переключает GPS в эмуляторе и
задаёт моделируемую позицию в Худжанде. Системные команды выполняет host runner;
  Android-тест подтверждает их применение через файлы в собственном cache.
После завершения GPS включён. Запускайте сценарий на выделенном виртуальном
устройстве без нужных данных и аккаунтов.

## Что проверяется

- Настоящий Android Firebase Auth отклоняет неверный код, принимает код локального
  Auth emulator, выдаёт пользователя с номером и корректно завершает сессию.
- Экран входа отправляет запрос через обычный `AuthService`, позволяет исправить
  неверный код, обрабатывает клавиатуру и возвращает пользователя в корень после
  входа. Запись профиля перехватывается тестовым репозиторием.
- Пассивная геолокация не запрашивает разрешение, постоянный запрет и выключенный
  GPS дают понятные ошибки; после восстановления разрешения Android-плагин
  возвращает заданную позицию с допустимой точностью.
- Настоящий экран заказа загружает картографические тайлы через HTTPS и оставляет
  доступным выбор адреса. Host runner сохраняет снимки карты и экрана SMS в
  каталог отчёта до удаления тестовой установки Flutter.
- Проверяется совпадение видимой булавки с координатой карты и сохранение
  выбранного города при позднем ответе с позицией вне зоны доставки.
- Модульные проверки отдельно покрывают узкий экран с крупным шрифтом и
  клавиатурой, а также скрытие демонстрационных адресов из обычного поиска.

## Границы

Геопозиция задаётся через ADB; это не измерение физического GPS. SMS-коды выдаёт
локальный сервер; проверка не подтверждает доставку SMS оператором, production
Play Integrity/App Check или FCM. Картографические данные требуют сети. Сценарий
не размещает заказ, не проверяет оплату и не заменяет выездную проверку курьера.

Настройка HTTP для localhost/10.0.2.2 находится только в Android debug manifest;
release сохраняет HTTPS. Тестовый entry point находится в `integration_test/` и
не вызывается обычным `lib/main.dart`.

Host runner использует основной Android user 0 и cache тестового пакета.
Он сбрасывает журнал перед запуском и записывает строки сразу, чтобы команды
разрешений не ждали буферизации вывода. Перед снимком проверяется фокус TajGo.
Ввод текста выполняет WidgetTester; физическая клавиатура и SMS-автозаполнение
требуют отдельной проверки на телефоне.

После native/debug-проверок собирайте release через
`scripts/build_android_release.ps1` или обычный `flutter build ... --release`
без `--no-pub`. Flutter должен заново сгенерировать регистрацию Android-плагинов
для release и исключить `integration_test`; регистрация debug-варианта для
release не подходит. Зафиксированный `pubspec.lock` сохраняется.
