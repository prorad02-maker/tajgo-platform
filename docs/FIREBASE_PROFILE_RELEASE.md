# Firebase: восстановление загрузки профиля

Дата проверки: 10 октября 2026 (Europe/Moscow).

## Причина

Приложение `tj.tajgo.app` использует проект `tajgo-4fcd0` и callable-функции
в `europe-west1`. При запуске `AppRouter` вызывает `ensureUserProfile`, затем
читает `users/{uid}`. На момент проверки `firebase functions:list` вернул
пустой список. Подключение Blaze не разворачивает эти функции автоматически.

База `(default)` существует в `nam5`. Опубликованные правила Firestore
разрешают пользователю читать собственный профиль. Их версия отличается
от локальной; для восстановления входа менять правила не требуется.

## Объём публикации

- `ensureUserProfile`: создание/загрузка профиля после авторизации.
- `completeUserProfile`: сохранение имени и завершение заполнения профиля.
- `acceptLegalDocuments`: сохранение принятия документов пользователем.

Публикация этих трёх функций не означает готовность заказов и доставки.
Для остальных команд нужны отдельная публикация, индексы и настройка
серверного расчёта маршрута; см. `RELEASE_READY.md`.

Runtime согласован на Node.js 22 в `firebase.json`, `functions/package.json`
и `functions/package-lock.json`. Локальная проверка использует Node.js 22.23.3
из официального архива Node.js, проверенного по SHA-256. Переносимая копия
находится в ignored-каталоге `build/tooling/`; системный Node не заменён.

## Проверки и публикация

Состояние: три функции опубликованы. Повторная проверка Firebase CLI
подтвердила `ACTIVE`, `gcfv2`, `nodejs22`, `europe-west1` для каждой.

- TypeScript lint/build: успешно на Node.js 22.23.3.
- Functions unit: 28/28.
- Firestore Rules emulator: 17/17 (проверены локальные правила).
- Functions integration emulator: 35/35.
- Flutter: 13/13 целевых тестов Firebase identity, authoritative core и legal URLs.
- Production callable: 3/3 возвращают HTTP 401 / `UNAUTHENTICATED` на запрос
  без авторизации. Это ожидаемый ответ работающей защищённой функции.
- `git diff --check` для изменённых конфигураций и интеграционных тестов: успешно.

В эмуляторные тесты добавлены сценарии первого входа, сохранения профиля,
повторного входа, сохранения роли существующего администратора и отказа
неавторизованным запросам. Все изменения тестовых документов выполняются
в проекте эмулятора `demo-tajgo`.

Команда ограниченной публикации (запускать с Node.js 22 в PATH):

```powershell
firebase.cmd deploy --only "functions:ensureUserProfile,functions:completeUserProfile,functions:acceptLegalDocuments" --project tajgo-4fcd0 --non-interactive
```

Осталось повторить вход на телефоне или нажать «Повторить» на экране ошибки
профиля. Проверка статуса и ответа `UNAUTHENTICATED` подтверждает доступность
callable и защиту входа, но не заменяет загрузку профиля авторизованным
пользователем на реальном устройстве. Телефон через ADB не подключён,
реальный вход после публикации пока не подтверждён.

Сайт, правила Firestore, индексы, роли пользователей и остальные функции
этой публикацией не изменялись. Пересборка установленного приложения
для появления указанных серверных функций не требуется.
