# TajGo: аудит и первый этап доработки — 10 октября 2026

Исходный commit: `11d6eb9`. Проверены структура приложения, зависимости,
запуск и роли, создание и отслеживание заказа, каталог и checkout,

## Исправлено в коде

- Дорожный routing включён в обычных сборках. Используется ранее выбранный
  публичный OSRM `routing.openstreetmap.de`, для велосипеда и автомобиля
  выбираются отдельные datasets. Настройки собственного сервиса сохранены.
- Реальный запрос Худжанд → Худжанд вернул `Ok`, 42 точки, 1786.6 м.
  Имя `driving` в URL этого сервиса используется и велосипедным dataset;
  режим выбирается `routed-bike` / `routed-car`, а не этим именем.
- Провайдер учитывает режим конкретного запроса; пользовательские OSRM URLs
  сохраняют prefix path и query. Неверные endpoint URLs отклоняются.
- Неверные метрики и геометрия маршрутов проверяются; начало/конец геометрии
  должны находиться не дальше 500 м от выбранных точек.
- Fallback остаётся доступным при отсутствии сети; он явно отмечен как
  предварительный и не выдаётся за дорожный маршрут.
- Завершение старого параллельного запроса больше не удаляет новый запрос
  того же маршрута из таблицы выполняющихся запросов.
- Выбор адреса отменяет старое обратное геокодирование. Движение карты сразу
  делает прежний адрес недействительным; подтверждение проверяет совпадение
  центра с координатами, для которых получен адрес.
- Начальная GPS-проверка не перезаписывает уже сделанный выбор пользователя.
- Сохранение недавних мест не задерживает переход этапа и не допускает
  повторного подтверждения во время записи preferences.
- Поиск сразу инвалидирует старый ответ, ещё до окончания debounce.
  Очистка строки отменяет отложенный запрос.
- Native geocoder получает подписи результатов по найденным координатам,
  включает номер дома и убирает повторение города. GPS и карта используют
  один formatter геокодера.
- `TajGoMapLocation` объединяет address/latitude/longitude и валидирует их.
  Заказ принимает pickup/dropoff целиком; старые Firestore поля сохраняются
  для совместимости. Order model предоставляет типизированные pickup/dropoff.
  Каталог использует ту же модель для выбранного адреса доставки.
- Обзор маршрута в каталоге не изменяет адрес доставки: выбранная точка
  сохраняется отдельно от камеры, отображается маркер B. Пользовательское
  перемещение сразу инвалидирует предыдущий результат.
- ETA обычного заказа берётся из ответа routing; карта учитывает нижнюю
  панель при показе всего маршрута.
- Общая тема полей, кнопок, карточек, нижних панелей и сообщений обновлена.
- Основные ошибки действий преобразуются в понятные сообщения. Клиентское
  отслеживание, курьер и списки заказов различают ошибки/загрузку/пустоту.
- Администратор попадает в защищённую административную навигацию;
  debug-обход role-check убран. Администратор может отменять waitingOffers.
- Ключи подписи, key.properties, env и service-account files исключены из Git.

## Оставшиеся задачи по результатам аудита

### Critical — до реальных пользователей

1. Серверная авторизация критических команд. Клиентские транзакции и Rules
   не заменяют authoritative backend для acceptance, цены, радиуса курьера,
   завершения и каталожного checkout. В проекте отсутствует Functions backend.
2. Код получения заказа доступен назначенному курьеру и проверяется клиентом.
   Требуется серверная проверка и отдельное недоступное курьеру хранение.
3. Проверить Rules в Firebase Emulator: роли, чужие документы, изменения цены,
   статусов и assignment. Локальное чтение Rules не доказывает безопасность.
4. Проверить фактически deployed rules/indexes, SMS Auth и разрешения двух
   тестовых аккаунтов. В этой сессии доступа к production Console не было.

### High — до выпуска

- Production routing с управляемыми квотами и доступностью. Используемый
  публичный endpoint обозначен владельцем как DEMO; собственный или договорной
  сервис не был найден в репозитории. Включение дорожного маршрута исправляет
  поведение приложения, но не закрывает эксплуатационную надёжность сервиса.
- Production keystore: при отсутствии android/key.properties текущая сборка
  использует debug-подпись. Она не является готовым Google Play релизом.
- Физический Android E2E: GPS, запрет permissions, SMS, customer/courier,
  потеря сети, background, restart. Доступны только Windows и Edge.
- Idempotency создания/предложений/checkout при timeout и повторном запросе.
- FCM, App Check, crash reporting и наблюдение за зависшими заказами.
- Проверить admin consistency: повторный расчёт статистики после dispute,
  очистка activeOrderId и возврат заказа без устаревших предложений.

### Medium

- Миграция старых/повреждённых заказов: неизвестный status сейчас становится
  waiting. Требуется безопасное отдельное состояние и inventory данных.
- Полный UI/UX pass всех реальных экранов, большого шрифта и клавиатуры;
  сделанный общий theme pass не заменяет визуальное приёмочное тестирование.
- Уточнение ручного адреса/ориентира, если native geocoder недоступен.
- Уточнить SLA таймстампы pickedUpAt/deliveredAt с согласованными Rules.
- Подтвердить фоновые уведомления и offline восстановление состояния.

### Cosmetic

- Убрать оставшиеся локальные hardcoded стили в пользу theme tokens после
  визуального согласования экранов клиента, курьера и администратора.
- Заменить шаблонный README и описание pubspec на инструкции продукта.
